# 로그인 없는 게시판에서 "내 글" 보호하는 방법 비교

로그인 시스템(회원가입/로그인)을 만들지 않기로 했으니, "이 글은 내가 썼다"는 걸
증명할 다른 방법이 필요합니다. 두 가지 방식을 비교합니다.

---

## 방식 A. 글별 비밀번호 (추천)

옛날 PC통신 시절부터 지금까지도 쓰이는 가장 흔한 방식입니다.
"회원 계정"은 없지만, "글 하나하나"에 비밀번호를 겁니다.

### 글쓰기 화면
```
닉네임: [        ]
비밀번호: [ **** ]   ← 이 글을 나중에 고치거나 지울 때 쓸 암호
제목: [                    ]
내용: [                    ]
      [                    ]
       [등록]
```

### 수정/삭제할 때
```
[수정] 버튼 클릭
  → "비밀번호를 입력하세요" 팝업
  → 아까 그 글 쓸 때 입력한 비밀번호와 같은지 서버에서 확인
  → 맞으면 수정/삭제 진행, 틀리면 "비밀번호가 틀렸습니다"
```

### 데이터베이스에는 이렇게 저장됨
| id | 닉네임 | 비밀번호(암호화) | 제목 | 내용 | 작성일 |
|----|--------|------------------|------|------|--------|
| 1  | 홍길동 | $2b$10$abc...    | 안녕 | ...  | ...    |

- 비밀번호는 그대로 저장하지 않고 **암호화(해시)** 해서 저장 (bcrypt 등 사용)
- 수정/삭제 요청이 오면, 입력받은 비밀번호를 같은 방식으로 암호화해서 DB 값과 비교

### 장점
- 실제 게시판들이 실제로 쓰는 방식이라 배울 가치가 큼 (비밀번호 해싱, 검증 API 등)
- "이 글의 주인만 수정 가능"이라는 게시판 본연의 기능을 구현하게 됨
- CRUD의 U(수정)/D(삭제)에 **권한 검사**라는 실전 개념이 자연스럽게 들어감

### 단점
- 비밀번호 입력/검증 로직을 추가로 만들어야 해서 코드가 조금 더 늘어남
- 비밀번호를 잊으면 그 글은 영영 수정 불가 (실제 게시판들도 마찬가지)

---

## 방식 B. 완전 개방형

닉네임만 입력하고 글을 씁니다. 비밀번호라는 개념 자체가 없습니다.

### 글쓰기 화면
```
닉네임: [        ]
제목: [                    ]
내용: [                    ]
       [등록]
```

### 수정/삭제할 때
```
[수정] 버튼 클릭 → 바로 수정 화면으로 이동 (누구나 가능)
[삭제] 버튼 클릭 → 바로 삭제됨 (누구나 가능)
```

### 장점
- 구현이 제일 단순함 (비밀번호 관련 코드가 아예 없음)
- CRUD 흐름 자체(등록→조회→수정→삭제)에만 집중해서 빠르게 익힐 수 있음

### 단점
- 아무나 남의 글을 지우거나 고칠 수 있어서, "게시판"이라기보다는 "다 같이 쓰는 메모장"에 가까움
- 실전 게시판에서는 거의 쓰이지 않는 방식이라 배움이 다소 얕음

---

## 비교 요약

| 항목 | A. 글별 비밀번호 | B. 완전 개방형 |
|------|-----------------|---------------|
| 구현 난이도 | 중간 (비밀번호 해싱/검증 추가) | 낮음 |
| 실제 게시판다움 | 높음 (내 글 보호가 됨) | 낮음 (아무나 수정/삭제 가능) |
| 배울 수 있는 기술 | 비밀번호 해싱(bcrypt), 권한 검사 API | CRUD 기본 흐름만 |
| 추천 대상 | 게시판의 실전 CRUD + 보안 개념까지 배우고 싶은 경우 | 정말 CRUD 흐름만 최소로 빠르게 익히고 싶은 경우 |

## 결론 (추천)

**방식 A (글별 비밀번호)** 를 추천합니다. 이유:
1. "게시판" 이라는 앱이 원래 가지는 핵심 기능(내 글은 나만 고칠 수 있다)을 실제로 구현하게 됨
2. 비밀번호 해싱 + 검증이라는, 실무에서도 그대로 쓰이는 개념을 CRUD 안에서 자연스럽게 배우게 됨
3. 코드 증가량은 크지 않음 (수정/삭제 API에 비밀번호 확인 로직 한 단계만 추가)
